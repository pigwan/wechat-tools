## 一、这次解决了什么

| 需求 | 落地内容 |
|---|---|
| 先做好日志，方便下次排查原因 | 掉线瞬间自动抓全量现场快照、结构化事件流、统一根因分类、一键复盘脚本；飞书告警直接带分类与快照路径 |
| 尽可能减少其他原因导致的掉线 | 内存探测 60s→300s、保活 5min→15min 且不再抢焦点、取消无效唤醒、单实例锁、版本失配预警、日志轮转 |

**必须说清的边界**：微信服务端使 PC 会话失效（提示「为了您的账号安全，请重新登陆」）是外部策略，**代码无法消除，也不应该绕过**。这次能消除的是「自伤型」因素：无效唤醒反复抢焦点、多实例重复读内存、客户端升级被误判成掉线、日志膨胀、诊断信息缺失。降低探测频率属于**降低可疑行为特征的预防性措施**，没有证据表明它能阻止服务端强制下线。

## 二、日志体系（下次掉线看哪里）

| 位置 | 内容 | 保留策略 |
|---|---|---|
| `diagnostics/incidents/INC-YYYYMMDD-HHMMSS.json` | **掉线瞬间的全量现场**：微信进程与启动时间、Weixin.dll 大小/SHA256/指纹匹配、窗口标题（含登录窗口）、可用内存、网卡/frpc/8080/8088、最近 15 分钟系统事件、bot.log 与 guard.log 尾部 | 最近 40 份 |
| `diagnostics/events/events-YYYY-MM-DD.jsonl` | 结构化事件流：guard_start / probe / incident / wake_skipped / wake_attempt / recovery / version_mismatch / error | 最近 14 天 |
| `wechat_guard.log` | 人类可读日志，带 reason 与快照路径 | 2MB × 3 份轮转 |
| `admin/wechat_health.json` | 兼容原有字段，新增 `reason` / `signals` / `last_incident` / `incident_file` / `guard_version` | 每 60s 覆盖 |
| `reports/掉线诊断_<事件ID>.md` | 复盘报告（运行诊断脚本后生成） | 手动保留 |

三类信息互相印证：`incidents` 回答「当时发生了什么」，`events.jsonl` 回答「时间线」，`wechat_guard.log` 用于快速扫一眼。

### 根因分类码

| reason | 含义 | 处置 |
|---|---|---|
| `awaiting_login` | 进程/DLL 正常但读不到绑定账号，客户端多半回到登录界面 | 人工重新登录；**唤醒无效** |
| `process_gone` | 没有微信主进程 | 启动微信，等待自动重连 |
| `core_dll_missing` | 进程里没有 Weixin.dll | 等启动完成；持续则查更新 |
| `version_mismatch` | DLL 指纹不在 `native_profiles` 中 | **更新内存 profile，不要按掉线处理** |
| `probe_error` | 探测代码自身异常 | 看快照里的异常信息 |
| `memory_pressure` | 内存过低且对象链短时不可读 | 关程序释放内存；通常不是主因 |
| `ok` | 在线（手动基线快照） | 无需处置 |

辅助信号 `signals`：`low_memory` / `login_window` / `frpc_down` / `port_8080_down` / `relevant_system_events` / `dll_recently_updated` / `wechat_child_process_spawned`。信号只作佐证，不单独定因。

## 四、稳定性改动明细

| 改动 | v1 | v2 | 目的 |
|---|---|---|---|
| 账号对象链探测 | 每 60s 读微信内存 | **每 300s** | 降低高频读内存这一异常特征与 4GB 机器的内存压力 |
| 状态心跳 | 与探测耦合 | **独立每 60s 写 `last_check`** | 保证 `health_monitor.py` 的 `guard_stale_seconds=180` 不误报「守护失联」 |
| 窗口保活 | 每 5min | 每 15min，且**不抢焦点** | 减少外部干预；`--nudge-minutes 0` 可完全关闭 |
| 掉线唤醒 | 每小时 3 次、共 39 次无效 | **仅 `memory_pressure` 时允许，每小时上限 1 次**；其余明确记 `wake_skipped` | 被强制下线时唤醒 100% 无效，还会抢用户焦点 |
| 版本校验 | 无 | 每轮轻量比对 DLL 大小，不匹配写 `version_mismatch` 事件 | 微信升级后偏移失配不再被当成掉线 |
| 单实例 | 无 | Windows 命名互斥体 | 防止两个守护同时读微信内存 |
| 日志 | 单文件无限增长 | 2MB × 3 轮转 + 按天事件流 + 快照数量上限 | 上次断线 12 小时刷了 2912 条等待日志 |

**权衡**：探测间隔变长意味着掉线发现延迟从最多 1 分钟变成最多 5 分钟。若要更快，用 `--probe-every 120`（折中）或 `60`（回到 v1 频率，但会恢复高频读内存）。

## 七、风险提示与常见坑

- **不要试图绕过微信登录校验**（自动扫码、伪造票据、多开），会放大账号功能限制风险；微信重新登录必须手机确认，目标是压缩恢复时间，不是消除重登。
- **不要把 `--interval` 设成 > 60**：代码内已强制上限 60s，这是为了兼容飞书监控的 180s 判活阈值；要调探测频率请改 `--probe-every`。
- **不要同时开两个守护**：v2 有互斥锁会直接退出第二个实例；旧版没有，切换时注意只留一个黑窗口。
- 快照里含进程路径、窗口标题与 bot.log 片段，`diagnostics/` 已加入 `.gitignore`；对外分享诊断报告前先扫一眼内容。
- 公网出口 IP 默认**不采集**（避免外部请求）。怀疑「光猫凌晨重拨导致 IP 变化」时，用 `set WX_BRIDGE_PUBLIC_IP=1` 再启动守护，快照会记录出口 IP。
- 快照采集含一次 200MB DLL 的 SHA256 校验和一次 PowerShell 系统事件查询，掉线瞬间约 1~3 秒，不会阻塞心跳超过 180s 阈值。
- 微信升级后若出现 `version_mismatch`，先更新 `vendor/helper-main/wxbot_framework/native_profiles.py`，**不要**按掉线去重新登录。
- 断线窗口内的消息仍无法回补，日报需标注数据缺口；这次改造不解决该问题。
