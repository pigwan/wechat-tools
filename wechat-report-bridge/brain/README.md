# 拟人大脑（brain）

微信群拟人决策引擎。**独立旁路应用**，和 `alert_monitor`（飞书告警）同一层级：

- 独立进程、独立配置（`config.local.json`）、独立状态库（`brain_state.sqlite3`，含记忆表）
- **只读** `server/messages.sqlite3` 的消息，**只写** `send_outbox.sqlite3` 的发送队列
- 不开端口、不碰 hook、不改任何机器人插件、不需要令牌
- 关掉进程 → 群聊立刻恢复现状，零残留

数据流：`消息库 → 拟人决策(+记忆检索) → LLM → 拟人延迟/拆句 → 发送队列 → report_bridge 插件发出`

## 当前状态（PHASE 0 + PHASE 1 已完成）

- **PHASE 0 决策引擎**：增量轮询、群白名单灰度、概率×精力/冷却/10分钟上限/安静时段、@识别、关键词触发、LLM 生成、拟人延迟、拆句、dry-run、自检、决策日志。
- **PHASE 1 长期记忆**：结构化记忆（事实/偏好/人物/梗/承诺/事件/自身）、艾宾浩斯遗忘曲线 + 情绪加权、相关记忆检索注入、被检索即复习、低权重自动归档 + 30天真删、铁律记忆永不遗忘、自动提炼。
- 未实现（后续）：性格/好感状态机、识图/表情包、人际关系星盘。

## 一、在网页里设置大模型 api/key（推荐）

打开管理台（`http://127.0.0.1:8088`）→ 左侧**应用** → **拟人大脑** → 「大模型设置」区：

| 字段 | 说明 |
|---|---|
| 接口地址 base_url | 默认 `https://api.deepseek.com`，兼容 OpenAI 格式网关 |
| 模型 model | 默认 `deepseek-flash` |
| API Key | 填入后**只回显末 4 位**，完整密钥不落到任何公开文件/接口 |

- 点**保存**写入 `brain/llm.local.json`（已加入 `.gitignore`）
- 点**测试连通**用当前配置发一句极简请求，验证 key 是否有效
- API Key 输入框**留空再保存 = 保持不变**，不会误清空
- brain 进程只读这个文件，不依赖网页运行；优先级：`网页设置 > config 指定文件 > 插件 llm_config.json`

> 填好 key 后，现有 `mention_chat` 等插件若也指向 `llm_config.json` 需单独填（两者配置源不同）。

## 二、网页勾选群聊白名单（关键：只有指定的群才生效）

打开管理台 → **应用** → **拟人大脑** → 「群聊白名单」区：列出消息库里所有群，勾选哪些群大脑就只接管哪些群。

- 支持按群名搜索、**全选当前/清空当前**（只作用于搜索结果）
- 点**保存白名单**写入 `brain/groups.local.json`（已 gitignore），下次轮询生效
- **未勾选的群完全不受影响**——消息照常采集，但大脑不会读取、不会回复、不提炼记忆
- 勾选的群若 `config.local.json` 里有专属参数（persona/概率等）就继承，没有则用默认模板
- 白名单为空 = 任何群都不启用（安全态）
- brain 进程只读该文件，不依赖网页运行；**网页一旦保存过，就以网页白名单为准**，不再看 config 里的 `groups.enabled`
- 尚未在网页设置过时，回退到 `config.local.json` 里 `enabled:true` 的群（兼容旧行为）

## 三、网页开关：总开关 + 演练模式

打开管理台 → **应用** → **拟人大脑** → 「运行开关」区：

| 开关 | 说明 |
|---|---|
| **启用大脑**（总开关） | 关闭时进程**不退出也不读消息**，进入待机（只写心跳）；网页一打开就恢复工作 |
| **被@必回** | 默认开。群里真@它时一定回，不受概率、冷却、安静时段限制（演练下仍只记录不发） |
| **演练模式 dry_run** | 开启时完整跑决策，但只写日志、**不发真消息** |
| **演练也调模型** | 开启（默认）时演练照样真实调用大模型，决策日志的「回复」列就是真实回复效果；关闭则用固定模拟文本、不花 token |

- **保存即生效，不用重启进程**：大脑每轮轮询都会比对配置文件的修改时间，一变就热重载，日志里会打一行
  `配置已热更新：总开关=开，演练=是，模型=真模型，被@必回=是，群=36，轮询=8s`
- 改群白名单、**被@必回**、演练开关都走同一套热更新；只有 `brain.py` / `memory.py` 代码本身改了才需要重启
- 点保存写入 `brain/runtime.local.json`（已 gitignore）；**网页一旦保存过就以网页开关为准**，不再看 config 里的 `enabled`/`dry_run`/`dry_run_llm`/`at_reply`
- 尚未设置过时回退到 `config.local.json` 的值（兼容旧行为）
- 其他参数（memory/top_k/频率/精力等）仍在 `config.local.json` 里改，同样热生效
- 实发模式下如果 key 失效，大脑会**暂停扫描并保留游标**（消息不会丢），补好 key 后自动恢复，不会拿模拟文本冒充回复发出去

灰度顺序：先保持 `enabled=true` + `dry_run=true` + 「演练也调模型」开着，用真实回复观察几轮措辞和分寸，确认合理后**只关掉演练模式**才真发言。

> 演练时**不会写长期记忆**（既不提炼新记忆，也不强化已有记忆权重），可以放心反复试跑。
> 网页日志页顶部的「演练模式 · 真模型 / 模拟文本 / 模型待命」徽章显示的是**当前进程实际**在用的模式。

启动（三种方式，任选其一）：

| 方式 | 命令 | 适用 |
|---|---|---|
| **统一启动台**（推荐） | 桌面「微信工具-启动.bat」 | 已集成，和接收端/管理台/守护/隧道一起起停，日志同窗口 |
| 带窗口单独跑 | `启动大脑.bat` | 调试，只看大脑日志 |
| 静默常驻 | `大脑_静默启动.bat` | 配合计划任务开机自启，日志写 `brain.log` |

统一启动台的规则：

- 大脑是它的第 6 个组件，排在最后启动（等消息库就绪再读），Ctrl+C 时一起关闭。
- **总开关关着也照常启动**，进程以待机方式待命（只写心跳），网页打开开关即自动开始工作，不需要重启任何东西。
- `--no-brain` 可临时跳过大脑；`--dry-run` 能看到"将启动/跳过 brain"的计划而不动任何进程。
- 接管模式会先停掉手动起的大脑进程（避免双实例），再以本窗口的管道输出重启。
- 想临时腾出窗口只看大脑：关掉启动台改用 `启动大脑.bat`，两者共用 `Local\WxBridgeBrain` 互斥体，不会同时跑两个。

自检（不启动主循环、不发消息）：`大脑_自检.bat`。

## 四、在网页里看日志

打开管理台 → **应用** → **拟人大脑**，页面里有两块日志：

### 1. 决策日志（核心）

大脑每扫到一条群消息就记一条，包括**没回的那些**，并写明原因。表格列：

| 列 | 含义 |
|---|---|
| 时间 / 所在群 / 发送者 / 消息 | 这条消息的上下文 |
| **决策** | `已回复`（绿）、`演练回复`（蓝）、`安静时段`/`冷却中`/`超频跳过`（橙）、`跳过`（灰） |
| **原因** | 翻成人话：`被 @ 到`、`命中关键词「大肥鱼」`、`概率未命中（正常跳过）`、`回复冷却中`、`10 分钟内次数已满`、`自己发的消息`、`未配置模型`、`模型报错：…` |
| 回复内容 | 实际会发出去/已发出的文本 |

顶部状态条显示：**运行状态**（运行中 / 心跳已停 / 总开关已关闭 / 尚未运行过）、心跳多久前、演练模式标记，以及已回复 / 演练 / 跳过 / 总条数统计。

- **群下拉框**可按单个群筛选，清空日志也只清当前筛选的群
- **刷新**重新拉取；数据来自 `brain_state.sqlite3` 的 `decisions` 表

### 2. 运行日志（排错）

同页「运行日志」区，点**查看最近 150 行**读 `brain/brain.log` 尾部 —— 这是大脑进程自己的输出（启动参数、每轮异常、遗忘巡检、LLM 报错）。以前只有带窗口启动才看得到，现在**静默启动也会落盘**，超过 2MB 自动滚动为 `brain.log.1`。

> 心跳判断：大脑每轮轮询（默认 8 秒）写一次 `last_tick`，超过 90 秒没更新即显示「心跳已停（进程可能未启动）」。所以「没有新日志」和「进程挂了」能一眼区分开。

命令行等价操作：`python brain.py --status`（游标 + 决策分类统计 + 最近 5 条）。

## 五、记忆管理命令

```bash
python brain.py --memory-stats     # 统计：活跃/归档/铁律/平均保持率/分类
python brain.py --memories          # 列出记忆（可加 --chat-id 只看某群）
python brain.py --extract           # 立即对所有启用群提炼一次
python brain.py --memory-clear --yes           # 清空全部记忆（不可逆）
python brain.py --memory-clear --yes --chat-id xxx@chatroom  # 只清某群
```

记忆随决策自动运转：回复时按相关性检索注入，回复积累够（每群 ≥8 条且距上次 ≥10 分钟）自动提炼一次，每天跑一次遗忘巡检。

## 六、拟人策略参数（按群独立）

| 参数 | 含义 |
|---|---|
| `reply_probability` | 普通消息被回复概率 0–1 |
| `energy` | 精力：发言越多越低、按分钟恢复，回复概率按精力缩放 |
| `cooldown_seconds` | 两次主动插话最小间隔 |
| `max_replies_per_10min` | 每 10 分钟主动插话上限 |
| `quiet_hours` | 安静时段 `[[0,8]]`，不主动插话（被@仍回） |
| `at_reply` | 是否响应真@。默认 **true**：被@必回，不受概率、冷却、安静时段限制 |
| `trigger_words` | 命中即回（不受概率限制） |
| `persona` / `personality` | 人设提示词 / 对齐现有群人格 |

### 响应速度（config.local.json 的 `rate` 与 `poll_seconds`）

一条消息从进库到发出去，耗时由四段组成：

| 环节 | 默认值 | 怎么调 |
|---|---|---|
| 轮询间隔 `poll_seconds` | 2 秒 | 越小越灵敏；有消息在等时会自动用 0.3 秒连扫，积压不会排队 |
| 大模型生成 | 1–4 秒 | 改 `llm.local.json` 的 `max_tokens`（默认 512）越小越快 |
| 拟人延迟（@）`at_min/max_delay_seconds` | 1–2.5 秒 | 被@时用短延迟，像"看到提醒就回" |
| 拟人延迟（主动插话）`min/max_reply_delay_seconds` | 2–7 秒 | 主动插话慢一点更像人，可调小 |
| 发送队列消费 | ≤0.5 秒 | helper 侧固定，不用改 |

拟人延迟是**排程**不是**等待**：`deliver_reply()` 只把"几点几分该发哪条"放进内存队列就返回，
主循环继续扫消息、继续生成。所以群里连来五条也不会一条条排队干等。

## 七、人设怎么来：你来配，不是它自己生成

人设是**配置项**，不是大模型自己编的。三层优先级（从高到低）：

1. 网页「应用 → 拟人大脑 → 人设」里给**某个群**单独填的（存 `brain/persona.local.json` 的 `groups`）
2. 网页里填的**默认人设**（同一文件的 `default`）
3. `config.local.json` 里 `groups.<群 id>.persona`，都没有就用内置模板

网页填的是纯文本提示词，例如：

> 你是群里一个爱接话、说话简短口语化的成员。不要自称 AI、机器人或助手。
> 回复控制在 1-3 句，偶尔用一两个语气词。别用"作为 AI 助手"这类说法。

保存后下一轮决策生效（热更新，不用重启）。`persona.local.json` 已 gitignore。

运行时还会自动往 system prompt 后追加两行，不用你写：群名、「群里的人叫你 X」、当前时间——
这样它不会说出"我不知道自己在哪个群"这种明显穿帮的话。

真正**自动生成**的是**长期记忆**（谁是谁、群里聊过什么、定过什么约定），
由 `memory.py` 按艾宾浩斯曲线从聊天记录里提炼，检索后注入 prompt。人设（说话风格）和记忆（事实）是两套东西。

写人设时把三件事说清，效果最好（每件事一两句就够）：

| 要写清 | 例子 |
|---|---|
| **是谁** | 许昌本地人，三十来岁，爱看电影，周末常带孩子 |
| **怎么说话** | 句子短、口语，不用"首先/其次"，少用感叹号，偶尔一句河南话 |
| **禁忌** | 不自称 AI，不主动提自己是机器人，不说教，不追问隐私 |

只写"你是一个友好的群成员"这种，回复会非常模板化——模型没有具体线索可依。

## 八、接话节奏：冷却是什么

「接话节奏」控制的是**它什么时候主动开口**，不控制"被叫到要不要回"。七项都能在
网页「应用 → 拟人大脑 → 接话节奏」里改，存 `brain/tuning.local.json`（已 gitignore），
保存后下一轮生效，不用重启。

| 参数 | 默认 | 含义 |
|---|---|---|
| 主动接话概率 `reply_probability` | 0.28 | 群里**没人叫它**时，每条新消息插话的概率。还会乘精力系数（0.15~0.7），实际概率通常更低 |
| 冷却秒数 `cooldown_seconds` | 90 | 回完一句后，这么久内**不再主动插话**。防止一个话题里连刷好几条 |
| 10 分钟上限 `max_replies_per_10min` | 6 | 10 分钟内最多主动插话几次，硬上限 |
| 跟进窗口 `follow_window_seconds` | 180 | 刚说过话后的这段时间算「同一段对话」，期间走下面的跟进参数；填 0 关闭跟进 |
| 跟进概率 `follow_probability` | 0.85 | 跟进时的接话概率（比开场高，才接得上话） |
| 跟进句数 `follow_max_turns` | 4 | 一段对话里最多连说几句，接满就交回给人 |
| 跟进冷却 `follow_cooldown_seconds` | 6 | 跟进时的冷却（比开场冷却短，反应才像人） |

判定顺序（`decide()` 里从上到下，命中即停）：

1. 自己发的 / 空消息 → 跳过
2. **被真 @（且开了「被@必回」）→ 直接回复，不看概率、不看冷却、不看安静时段**
3. 命中 `trigger_words` → 回复
4. 处于安静时段（默认 00:00–08:00）→ 跳过
5. 距上次回复不足冷却 → **冷却中**（`cooldown_seconds`；如果在跟进窗口内则用 `follow_cooldown_seconds`）
6. 10 分钟内已达上限 → 超频跳过
7. 掷骰子：概率 × 精力 → 命中回复，否则跳过（跟进窗口内用 `follow_probability`）

**为什么有「跟进窗口」**：如果每条消息都按开场概率独立重掷，会出现"接了一句，下一句又回到
16% 的冷启动概率，话题聊到一半突然不吭声"的假象。跟进窗口让它在刚说过话的 3 分钟内用 0.85
的高概率继续跟、冷却缩到 6 秒，接满 4 句自动收手，把话头交回群里。
注意概率仍乘精力，所以一口气说完几句后精力下降，跟进概率也会自然回落。

所以日志里的「冷却中」= 它最近刚说过话，还没到下一次能开口的时间，**不是出错**。
如果觉得 90 秒太长，把它改成 30 或 0 即可；但改太小容易在活跃群里连续接话，看起来像刷屏。

**只想让它"被@才回、绝不主动插话"**：把主动接话概率改成 `0`，冷却随便填。这样除了 @ 和
关键词触发，它完全不吭声。想让"接上话就别半路消失"更明显，把跟进概率调高（0.85→0.95）、
跟进句数调大（4→6）；反过来觉得它太能聊，把跟进窗口填 `0` 就退回每句独立重掷。

## 九、安全

- 群启用完全由网页白名单控制：未勾选的群大脑绝不介入；`self_wxid` 自动从 `bot_config.json` 读取，跳过自己发的消息
- 频率/概率/精力三道闸防刷屏；冷却和上限按群独立
- 密钥只存 `brain/llm.local.json`（gitignore），接口只回显末 4 位；base_url 拒绝公网 http
- 演练模式默认也真实调模型（可在网页关掉「演练也调模型」改走本地模拟文本，不花 token）；没配 key 时自动回退模拟文本，不会崩
- 继续遵守：独立微信副本、小号、不绑支付
